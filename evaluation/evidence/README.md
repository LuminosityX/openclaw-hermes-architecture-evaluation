# First-wave exploratory execution, 2026-10-26

The [bounded evidence record](first-wave-20261026.json) contains actual OpenClaw Gateway observations using the existing `2026.9.2` build, declared source commit `3928bad9badfcb6c7d140530435e806fb8092190`. Controller hashes match the retained Python source. The build pin comes from installed metadata, not an independently verified upstream-source rebuild. This is a two-block pilot of each of three studies, not a confirmatory architecture verdict or completion of the full case matrix.

The final sequential first wave took 123.72 seconds with a local scripted provider and no paid model calls. It used read-only shared dependencies, a 64 MiB kernel-limited tmpfs, zero allowed swap, a 1 GiB whole-experiment memory limit and two-core CPU quota. The storage guard deliberately reached `ENOSPC` before product startup and removed its files. Each arm's runtime state was deleted after compact observations were collected; namespace teardown removed remaining keys, caches and temporary data. The retained JSON is about 222 KiB; there is no runtime snapshot or compressed raw archive.

| Study | Direct observation | Limit of interpretation |
| --- | --- | --- |
| ARC-01 | Both cap-1 batches completed all 8 tasks at approximately 3.10 tasks/s. Both cap-4 batches completed all 8 at approximately 5.52 tasks/s. Actual effect overlap was 1 versus 2; all 32 tasks had exactly one independent receipt and a matching receipt in native SQLite. | A fixed 150 ms synthetic effect on a resource-capped shared host; configured concurrency 4 did not become four overlapping effects. No production scaling ratio, durability guarantee or task-reasoning claim. |
| ARC-03 | In both blocks, a second session saw the canary in agent-scoped SSH workspace reuse and did not see it in its own session-scoped workspace. Revisiting the writer preserved its canary in both configurations. | Native SSH workspace ownership, not Docker behavior or hostile-tenant isolation; the shared SSH OS identity could still explicitly address sibling paths. |
| ARC-02 | In-process 600 ms plugin blocks coincided with neighbor latencies around 763/772 ms, versus 279/288 ms for the external MCP route. Native plugin `exit(42)` ended the Gateway in both blocks; external-tool exit left the Gateway alive and independent neighbor requests succeeded. | Small exploratory route comparison, with transport/interface differences. It does not estimate real fault rates or prove that process isolation alone explains the full latency difference. |

The whole-run memory ceiling was contacted (`memory.events max=417`) without an OOM or OOM kill. CPU quota throttling also occurred. Do not use these values as unconstrained product performance or a minimum-memory requirement. Product process-tree samples include startup and warmup; SSH server resources and whole-run cgroup values have different component scopes and must not be summed blindly.

Two earlier fixture setup attempts used an invalid combined `allow`/`alsoAllow` configuration or the wrong MCP tool name. They were corrected against the installed runtime and are recorded separately as harness errors, not OpenClaw product failures. A default-Docker probe also produced the native missing-backend error before any provider dispatch; no engine or image was installed. The successful scope pilot instead used an owned loopback OpenSSH backend with ephemeral synthetic keys.

These observations establish a working measurement path and concrete hypotheses for the next experiments. Six-axis coverage is still incomplete: broad privacy/authority probes, real-model quality, actual token charges, queue-phase attribution, long-run growth and complete trace/export behavior remain unmeasured. No product score or claimed designer intent is generated.
