# EXT-02: tool, provider and full harness ownership

The four frozen scenarios each have three independent native cloud units after whole-family calibration. All use a public bounded integer-addition task. They test integration ownership, not model quality; no paid model is used.

- S01 invokes the actual native stdio MCP tool. The real Python child computes the supplied integers and records its PID, result and an independent effect receipt. The native provider/tool loop still owns the turn.
- S02 adds a reference provider plugin through `api.registerProvider`. Its actual `wrapStreamFn` invocation must be recorded, and it calls the original prepared stream unchanged with generic compatibility explicitly preserved. Actual native MCP computation and receipt controls are still required. A manifest or registration alone is incomplete.
- S03 selects a separately registered `AgentHarnessV2` through the native session RPC. Actual `runAttempt`, versioned host capability checks, a distinct Python executor and the actual arithmetic result are required. The reference is literally tool-free and host-only: it exposes no native, dynamic, MCP, shell or model-callable tools and rejects any task outside bounded addition. Core retains admission, policy and canonical session identity. The supplied public user recorder and public `session-transcript-runtime` API persist actual messages; no private imports or native database writes are used. Native public history must expose the real answer. Arithmetic execution has no provider token usage; zero usage describes the deterministic fixture, not a billable model inference.
- S04 makes the actual external child fsync its own input-bound arithmetic checkpoint and exit 73 before returning an answer. Any host retries remain visible. An explicit Gateway restart then continues the same native session and exact public task. The external process must reuse the matching checkpoint with one computation, and the actual native transcript must contain its answer. This does not claim automatic framework recovery or exactly-once external business effects.

The external reference stores only its own small JSON checkpoints under the owned workspace. Each file is bound to the complete public task. Process output, task integers and input size are bounded; the child is killed on observed abort or its ten-second deadline. Host authority is checked after awaits and before process launch and native transcript writes. This is an unsandboxed explicitly selected trusted plugin, not an extension security sandbox. All installations and at most 128 MiB temporary experiment state remain on disposable GitHub workers.
