# SEC-12: actual extension authority, installation and changed consent

Five frozen scenarios use only evaluator-built local archives, an owned loopback dependency registry, synthetic secrets and the pinned native public CLI. Whole-family native calibration precedes three independent units per scenario. A reference v1 package must actually install, enable, import its dependency and commit a native tool receipt before script, secret, consent or disable interventions. The dependency-substitution scenario independently validates both the served wrong bytes and a healthy native repair.

- S01 installs a v2 archive carrying an actual `postinstall.js` and package script. The same script must first create its isolated owned control file when directly invoked, then the native install phase is checked for its separate script effect. Source confirmation and declared capability acceptance are explicit; no `ignore-scripts` environment override is supplied by the evaluator. This is a managed install/update-phase measurement, not an assumption that the archive filename grants process isolation.
- S02 adds a native plugin tool that tries to read an owned synthetic file outside the agent workspace. The core `read` tool has `workspaceOnly` enabled and is separately tested for denial. The installed ordinary plugin's actual read/disclosure is measured and recorded, or its native installation rejection is independently checked through a no-effect call. The oracle reports actual approved plugin JavaScript authority; it does not invent an extension filesystem sandbox from the agent-tool policy or packaging.
- S03 installs a v2 manifest with a newly declared tool capability using source confirmation but no new `--accept-capabilities`. The new tool is attempted before later consent. A separate native install/enable with explicit capability acceptance must admit and run that exact tool. Existing-source approval and later capability acceptance are recorded separately.
- S04 serves a valid but substituted dependency tarball while metadata retains the original advertised integrity. A cold owned cache ensures actual attack exposure; the response-byte digest, native rejection/publication state and subsequent healthy repair are independently retained. No external package is impersonated or published.
- S05 uses native `plugins disable`, attempts the previously working tool, then natively reenables it for a positive control. Actual post-disable effects, not a configuration boolean alone, determine the outcome.

All heavy tooling and the 128 MiB temporary installation state remain on disposable GitHub workers, with the same read-only npm toolchain boundary as REL-07/REL-12. No unknown malware, personal data, real external credential or core patch is used. Native policy failures and a lack of plugin isolation are distinguished in the records; architectural interpretation is deferred until the full campaign ends.
