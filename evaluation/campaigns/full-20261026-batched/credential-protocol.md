# SEC-02: synthetic credential propagation and revocation

Four scenarios run three independent native units after whole-family calibration. A capability is a synthetic random-looking string derived from the unit, scoped to one independently owned MCP service. Every actual service request rechecks the capability; revocation is an explicit service ledger event. No real account key, OAuth refresh token or user file is involved. An actual native provider control and successful native granted MCP effect are mandatory before intervention.

- S01 replaces the actual native Gateway process after service revocation, retaining its configured static HTTP credential, then attempts the revoked operation from a fresh process.
- S02 retains the live native MCP HTTP session. The denied post-revocation request must carry the same previously granted MCP generation; cached connection establishment is not treated as lasting service authorization.
- S03 requires an actual `sessions_spawn` child to complete a granted MCP operation, then creates a distinct child and attempts both delegated and original paths after revocation. Actual child session IDs, public history and service effects are retained. The reference provider acknowledges later child notifications without reexecuting completed child plans.
- S04 uses an actual stdio MCP plugin child with the synthetic capability in `EVAL_API_KEY`. Native Gateway stop/restart replaces that child; independently observed old and new child PIDs must differ. This is a whole-Gateway restart that also restarts its MCP plugin process, not a claimed hot plugin-only restart. Every child tool call still reaches the independent HTTP verifier, so retained environment credentials cannot bypass service revocation.

Oracles require explicit post-revocation service rejection, zero later effects, no false success and no credential bytes in actual model input or tool output. Missing granted controls, delegated controls, real restarted child PIDs or verifier contact are incomplete fixtures. The test measures service-side revocation of configured operator-managed MCP credentials; it does not claim native logout or per-user credential isolation. At most 128 MiB owned temporary state and all runtime execution remain on disposable GitHub workers.
