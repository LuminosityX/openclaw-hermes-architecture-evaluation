# EXT-07: declared external artifacts and actual integration routes

Four frozen scenarios run three fresh independent units after whole-family native calibration. The corpus is deliberately small and owned: one stdio MCP arithmetic server definition, one VS Code command-extension SDK package, the public native arithmetic harness adapter and one dependency-free OpenClaw lifecycle plugin. Corpus SHA-256 values and actual native command results are retained. Results do not establish compatibility with every third-party artifact.

- S01 preserves the external MCP server's command/args object from a `mcpServers` JSON artifact and imports it through the documented native `mcp set` CLI. The root registry mapping is explicit. The actual native MCP child must compute the supplied integers, return the real result and commit an independent receipt. This reuses the integration mechanism from EXT-02 but executes fresh native work; earlier observations are not promoted.
- S02 installs and executes an ordinary native plugin first, then attempts native installation of the foreign SDK archive unchanged. That owned artifact follows the [documented VS Code manifest and activation SDK](https://code.visualstudio.com/api/get-started/extension-anatomy): `engines.vscode`, `main`, command contribution and `activate(context)` calling `vscode.commands.registerCommand`. A rejected direct integration is classified unsupported only when actual native diagnostics establish the host-contract mismatch. A generic installer error remains incomplete. The native plugin must still work afterward. No VS Code host is installed or claimed to have been tested, and native support for other foreign bundle formats is not inferred.
- S03 uses the documented public `AgentHarnessV2` adapter with its actual native model-catalog registration, run callback, separate Python process and real public transcript persistence. It freshly executes the declared external harness corpus; a callable MCP tool is not counted as full harness replacement.
- S04 installs and executes native v1, records the actual tracked `plugins update` result, explicitly replaces the local archive through the documented `plugins install --force` path and verifies that the same native tool executes actual v2. The tracked update and local-archive replacement are distinguished. Native uninstall must prevent subsequent tool dispatch and retain its documented explicit disable marker. No install index or runtime state is manually fabricated.

All native cores remain unmodified. Existing npm executable tooling may be mounted read-only on disposable workers; no host project dependencies are exposed or copied. Runtime installations, caches and at most 128 MiB temporary native state remain on GitHub-hosted workers. No paid model is called.

Native contracts: [MCP registry](https://github.com/openclaw/openclaw/blob/157d8c2bc3ea2fa183afdc11088e69690bf8e64e/docs/cli/mcp/registry.md), [plugin install source confirmation](https://github.com/openclaw/openclaw/blob/157d8c2bc3ea2fa183afdc11088e69690bf8e64e/docs/cli/plugins/install.md), [native update/uninstall semantics](https://github.com/openclaw/openclaw/blob/157d8c2bc3ea2fa183afdc11088e69690bf8e64e/docs/cli/plugins/uninstall-and-update.md).
