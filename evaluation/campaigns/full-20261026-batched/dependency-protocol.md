# REL-07 / REL-12: managed dependency reconstruction and installation repair

The frozen four scenarios per family execute the actual pinned `openclaw plugins install`, `plugins inspect` and `plugins enable` commands, followed by a real native task importing an owned npm dependency and committing an independent receipt. Each family has whole-family calibration and three fresh independent units per scenario. The evaluated installation surface is native managed extension dependencies; this is not a claim about relocating OS native binaries or reconstructing the core npm installation.

A tiny loopback-only registry serves one synthetic package. Plugin and dependency archive hashes, advertised SHA-512, HTTP faults, native install/inspect output, actual dependency version and independently observed effects are retained. The namespace has no outward route and receives no project/global dependency tree. Only the existing npm CLI package and its own tooling dependencies are mounted read-only, with its version and executable hash recorded. No extra local tool, OpenClaw installation or cache is created on the user's computer. Each hosted unit has 128 MiB tmpfs; all installation state is removed afterwards.

REL-07 exercises an empty owned cache, a cache seeded by a verified native install followed by an offline native reconstruction, a registry 404 for a required dependency, and an actual mismatch between advertised integrity and tarball bytes. Missing/integrity arms must not claim a successful complete publication. Healthy native repair, using the same immutable plugin archive, separately validates the fixture and real imported dependency. Offline reconstruction cannot silently use a host module cache.

REL-12 exercises an actual prematurely closed tarball body with an incomplete Content-Length, mismatched SHA-512, an npm cache path on the read-only core mount, and an actual installer process-group kill while its dependency HTTP response is gated before publication. Native exit status and installed-index publication are measured before repair. The same archive is then retried through native installation with only the owned registry/cache restored. The evaluator never copies a dependency tree, writes the native installed index or fabricates repair success.

The registry explicitly disables npm fetch retries and uses a five-second fetch timeout to bound fault waiting; these settings are recorded as fixture conditions rather than inferred defaults. Cold/offline conditions and fault-specific registry events are independently checked. Failed healthy positive controls remain harness failures, not completed product observations. Native installer rejection/repair failures after a proven fixture remain separately visible.

The owned registry shape follows the [pinned first-party npm installer fixture contract](https://github.com/openclaw/openclaw/blob/157d8c2bc3ea2fa183afdc11088e69690bf8e64e/src/plugins/test-helpers/npm-registry-fixtures.ts); only the public CLI is invoked, not the product's test helpers or internal install functions.
