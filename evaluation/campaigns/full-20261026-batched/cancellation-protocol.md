# REL-05: actual queued, synchronous, descendant and checkpointed Stop

Four frozen scenarios each run three independent native units after whole-family calibration. A real operator WebSocket is connected before active work begins. Its actual `sessions.abort` socket write and native response are independently timed; a request being sent is not treated as an effective Stop acknowledgment.

- S01 occupies the native worker slot and requires actual native queued custody for the target HTTP task. Stop must prevent that queued target from dispatching, while the unrelated original slot owner still completes once after release.
- S02 runs actual synchronous JavaScript in a trusted native plugin. The plugin writes an owned entry marker and spins only until the controller removes its gate file or the five-second safety deadline. The pre-connected operator writes Stop during that synchronous window. Whether the Gateway can respond within 500 ms before the loop is released is measured explicitly. The fixture records actual effects and response order; it does not claim that already-started trusted plugin code is an independently killable process or that earlier effects can be undone. A safety timeout invalidates the timing fixture.
- S03 spawns an actual native child that reaches a cooperative remote MCP tool gate. The actual parent's subsequent model request is also held, proving both parent and child work are live when Stop targets the parent. The independent MCP service must receive a cancellation notification for the real child call and avoid its uncommitted effect. Returned native child identity and its public history are retained. An actual successful MCP transport control is required first.
- S04 selects the tested public native reference harness. It registers and clears its actual active-run handle through the public SDK, forwarding Stop to its owned child process group. Its separate Python child fsyncs an input-bound pure-arithmetic checkpoint and blocks at an independent HTTP gate. The child must actually be alive before Stop; exit within two seconds after the native response is independently checked. After an actual Gateway restart, explicit continuation in the same native session must reuse that exact owned checkpoint, preserve one computation and return its real answer. This demonstrates the declared harness checkpoint integration, not automatic checkpointing of arbitrary tools or rollback of business effects.

Gate entry, live descendant PID, queue custody and actual request writes are mandatory. Missing controls and gate timeouts remain incomplete. All native core source and storage are unmodified. Kernel/OS process state, MCP cancel/effect events, native operator responses and original public session records are retained in bounded cloud evidence. Runtime execution and at most 128 MiB temporary state remain on disposable GitHub workers; no paid model is called.
