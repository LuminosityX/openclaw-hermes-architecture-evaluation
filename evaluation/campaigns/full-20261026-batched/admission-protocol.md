# REL-01: request, committed custody, client ACK and dispatch

Three frozen scenarios each run three independent native units after whole-family calibration. The exact public `chat.send` method first admits and executes an independently receipted control. Each measured request has one persistent synthetic device identity, one native session and one stable idempotency key. The explicit later retry retains all three identities. A native asynchronous ACK is never confused with a completed effect. The native public session may already say `running` while its actual model worker is waiting for the global slot; the fixture therefore joins the exact ACK run ID to native active custody and separately proves pre-worker timing with the occupied slot and absence of target provider dispatch, rather than demanding a misleading `queued` status label.

- S01 holds the chosen request frame in an owned loopback proxy before forwarding it to native admission, then kills the actual Gateway. This is a concrete pre-admission/before-append cut, not an invented internal SQLite hook. The observer proves that the client had connected and completed native authentication/health, while the target request had not been forwarded. No client ACK or spontaneous recovered effect is expected before explicit delivery.
- S02 occupies the actual native worker slot, forwards the target request and holds the actual native response frame before the client can receive it. The response must be a successful native ACK. Independent read-only SQLite connections must find a committed target record, native public history must identify active custody for that exact ACK run ID, and the target must not have reached its model worker. The Gateway is killed while the client ACK remains held. This separately records durable-but-unacknowledged ambiguity.
- S03 occupies the same actual worker slot, lets the client receive its successful native ACK, requires independently committed target custody and native custody for the exact ACK run ID, then kills the Gateway before target provider dispatch. Automatic completion is observed for a predeclared twenty seconds after restart; missing acknowledged work at that deadline is a failed observation. An explicit same-identity retry then measures repair and duplicate dispatch separately.

The network proxy forwards original native envelope bytes unchanged and holds only the exact selected request or response ID. It uses owned loopback ports, never external infrastructure. Durable records are read through independent SQLite connections with bounds of 500 rows per table and 16 MiB inspected text; a negative bounded scan alone is not a global absence proof. Exact uppercase token boundaries exclude similarly prefixed baseline/control tokens from committed-row matches. No database, native source, ACK payload, device grant or idempotency record is edited. Native restart state, actual client results, raw ACK identity, independent effects and monotonic boundaries are retained. Kernel/power-loss durability is outside a committed-visibility and actual-process-crash test. Every gate has a safety deadline; timeouts and unexercised queue boundaries remain incomplete.

All execution and at most 128 MiB temporary state remain on GitHub-hosted disposable workers.
