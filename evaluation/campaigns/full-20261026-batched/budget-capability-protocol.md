# COST-05: probe the native quota capability before pooled-budget experiments

The frozen family requires concurrent siblings, retry, tool/model interaction and restart to compete for the same task budget. A per-session goal guardrail must not silently replace a task-tree pool, and a custom quota plugin must not be called native OpenClaw behavior.

The probe first verifies the actual pinned native `create_goal` and `get_goal` tools with an explicitly requested synthetic 5,000-token goal. The operator pauses this probe goal through its real public operation, avoiding unintended autonomous work. One actual native parent then issues two real `sessions_spawn` calls; both child sessions must execute their own `get_goal` and report their independent empty goal scope. The original parent budget remains independently readable. The native model-advertised goal schema, exact tool results and session relationships are retained.

Each scenario adds its actual contextual capability check: S01 uses the real siblings; S02 injects one actual local-provider 503 and requires native retry to complete one effect; S03 requires a real native MCP request timeout after a working transport control; S04 restarts the actual Gateway and checks that the original per-session goal ID and budget survive. These positive native mechanisms do not manufacture a shared pool.

Only after all controls succeed may a scenario be recorded as verified nonapplicability of the required **builtin shared task-tree budget pool in this pinned native budget surface**. The support contract is fetched at the exact core commit, checked against committed source hashes, mounted read-only and retained byte-for-byte with its license. It includes the native goal tool schema and its current-session scope implementation, the documented distinction between a session-goal guardrail and a billing cap, and separate child token/context ownership. Other provider billing limits or externally authored budget managers are not ruled out or substituted.

The existing frozen-plan rule keeps verified nonapplicability separate from measured coverage. Six independent hosted capability checks per scenario are retained, but they contribute no statistical performance samples, no claimed overshoot measurement and no fabricated provider cost. Missing adapters, failed controls, an unavailable environment or an absent contract remain incomplete. All runtime execution and at most 128 MiB temporary state remain on disposable GitHub workers; no paid model is used.
