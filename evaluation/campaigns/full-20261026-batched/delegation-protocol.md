# REL-03: delegated native work, child continuation and a real expired owner

Three frozen scenarios run three independent formal units after whole-family native calibration. The actual `sessions_spawn` result, live child session, native transcript and independent MCP call/effect ledger must exist before intervention. The external peer is independently hosted by the evaluator and may continue after a native process disappears; it is not called an independent native agent process.

- S01 kills the actual Gateway and all its native runtime descendants while its real delegated child's remote operation is waiting before effect commit. The parent/Gateway restart stops in-process native loops. The old remote operation is released only after the replacement native Gateway is ready; late response attachment, phantom child activity and automatic operation replay are checked independently.
- S02 stops the actual child through `sessions.abort` after its remote effect has committed but before the reply returns. The same Gateway remains live. It then explicitly continues that retained native child conversation through the public API. The extra unkeyed effect after an explicit operator retry is recorded separately from framework automatic replay; no exactly-once external-effect promise is invented.
- S03 freezes the exact native-runtime cgroup, excluding the evaluator. Its persisted real `gateway-owner/global` lease is observed through independent read-only SQLite until the actual five-minute expiry passes. No timestamp, source or database row is modified. A second real Gateway probes the same state on a different loopback port while the original physical coordinator still exists. The pinned contract expressly separates logical expiry from the physical coordinator fence. Only after observing that outcome are the original runtime processes actually killed, a replacement owner started and the old external result released.

The native owner PID must belong to the actual frozen subtree, the evaluator must not, kernel `cgroup.events` must confirm the freeze, and the persisted owner/expiry must remain independently readable. A separate tiny owned process first proves freeze/kill behavior. The five-minute wait is real and occurs on the disposable worker, while other experiment families can continue in GitHub.

The reference provider acknowledges interrupted-child notifications without deciding an implicit business retry. Native protocol replay remains visible to the independent MCP ledger. The child/Gateway distinction, actual session status, owner hashes, expiry timestamps, late reply attempts and explicit operator continuation are retained. Missing native controls or an unexercised expiry remain incomplete. The external request/gate has a finite eight-minute bound, and the complete family unit retains its ten-minute controller bound. All runtime execution and at most 128 MiB temporary state remain on GitHub workers; no paid model is called.
