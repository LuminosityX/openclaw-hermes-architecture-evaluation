# REL-08: real Linux source and native Windows target

The dedicated workflow uses an actual Ubuntu GitHub VM and an actual `windows-2025` GitHub VM, each running the same pinned OpenClaw package and Node build. The target checks Python's native OS, the verified Node binary's `win32` platform and an actual Windows Job Object. Generic Linux runs, emulated OS labels, syntax checks and upstream CI cannot enter the cross-OS formal binder.

One paired whole-family calibration precedes three independent paired units. Linux first executes the semantic fixture, creates and verifies a native full backup, and independently inventories its archived transcript rows. Exact archive/source hashes and the workflow/run identity bind the Windows job to that actual Linux execution. Each independent unit has fresh native state; no earlier experiment results are promoted.

- S01 exercises actual native file tools with Unicode, spaces, UTF-8 bytes and case-distinct source artifacts. Native filesystem case behavior is measured explicitly; a Windows case difference is not automatically called a security flaw.
- S02 proves the owned Python command in the actual host shell first, then starts it through native `exec`, observes a real heartbeat and kernel process identity, obtains the genuine native `process list` handle and requests native termination. PID reuse is excluded through native process creation identity. Heartbeat/exit observations precede any independent cleanup. PowerShell is used on Windows as the pinned core documents; no WSL or Linux-container substitute is used.
- S03 uses the actual Windows `backup restore` command on the independently verified Linux archive. The staged inventory compares every column and native transcript identity with the **archived** Linux snapshot, avoiding confusion with deliberate backup sanitization before transport.
- S04 performs the documented offline activation: manifest-selected state/workspace assets, explicit configuration path mapping, native Doctor and actual Gateway restart. No native database rows are edited. The same native session ID and original message IDs must survive, and the next actual native tool read must consume a real restored public artifact.

All fixtures are synthetic. Real GitHub tokens and provider keys are excluded from native child environments. Runtime/cache installation is capped at 4 GiB per disposable host. Linux uses an owned 3 GiB/no-swap cgroup, 128 task limit and two-core quota; Windows uses a real 3 GiB commit-limited/128-process/two-core Job Object. These kernel-specific memory counters are not pooled as comparable RSS measurements. Experiment state has a sampled 128 MiB guard, and each raw hosted evidence bundle is limited to 8 MiB. Source/target artifacts and native logs stay in GitHub; no runtime is installed on the user's machine and no paid model is called.
