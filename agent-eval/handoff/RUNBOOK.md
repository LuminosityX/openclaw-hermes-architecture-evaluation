# 执行手册

从此目录执行命令。所有路径和命令都只操作实验副本，不修改用户的默认 Agent 配置。

## 0. 纯本地准备

```bash
python3 tools/self_check.py
python3 tools/preflight.py
```

`preflight.py` 不读取密钥、认证文件或完整环境变量，也不启动四个 Agent；只列可执行文件与版本探测的待办。
实际版本命令需要适配负责人确认不会触发更新或登录后再运行。记录模型别名背后的实际版本及日期；别名不等于不可变快照。

## 1. 适配与授权

填写 `records/availability.csv` 和每家的 `records/adapter_*.json`。必须包括：

- 产品/组件/版本，CLI、Desktop、Web、Mobile、Cloud 中具体使用哪一条路径；
- 固定模型与推理强度如何配置，主/子/辅助调用如何验证，是否有无法配置的内建审查模型；
- 工作区、会话和持久状态属于哪个主机，受保护目录与允许出站端点；
- 启动、追加指令、停止、取回日志/usage/产物的已验证方式；
- 费用来源、授权账号类别、套餐/额度与外部工具成本（不得存真实凭据）；
- 评估材料隔离方式及固定服务档；不要继承用户日常的 priority/fast 或模型默认值。

本包没有能替代真实核验的“通用启动命令”。先查安装版本的 help 和官方文档，再把有效命令写入适配记录。
不要调用公开设置脚本去覆盖用户全局配置。优先使用产品正式支持的隔离 profile/实验 home；相关环境变量由适配负责人验证。

`records/authorization.json` 中预算和授权仍为未落实。填好批准范围、金额/credits 上限、每次最长等待及云资源上限后，才可开始真实调用。
如只使用已付费订阅，也要明确允许消耗的额度和并发限制。中途取消、失败和重试同样计入总用量。

## 2. 试跑（只做 24 次）

试跑一律用变体 v1、repeat 1；按 `pilot_order.csv` 的交错顺序执行。此轮是校准测试，不产生最终排名。

```bash
python3 tools/prepare_run.py --family openclaw --task W1 --variant v1 --repeat 1 --phase pilot
```

命令只创建工作区和运行记录，不启动模型。把输出工作区中的 `PROMPT.md` 交给对应被测产品的新会话。
代码任务提交前不要把黄金答案、隐藏测试或本 thread 的分析告诉被测产品。准备用时与正式执行用时分开。

运行结束后：

```bash
python3 tools/evaluate.py --run runs/pilot/openclaw/W1/v1/r1
```

验收器仅针对 W1—W4 的测试输入做本地验收，不能验证模型、费用和真实运行来源。
验收器会执行被测代码，本身不是安全沙箱；正式运行使用无业务凭据的受限评估环境。离线自检只执行本包生成的测试与参考实现。
W1/W2 的隐藏测试与 W3 的黄金文件由协调者检查；W4 机器检查只核对结构/引用形式，必须人工审阅语义。
W5/W6 采用手动执行清单，不能仅根据生成了一个文件就自动算通过。

填写 run 目录下的 `run_record.json`，保存原始 transcript、usage、账单/credits依据、产物和实际进程/云任务状态。
原始敏感记录如有需要本地受限保存；对外报告脱敏，但不能通过脱敏把失败或模型变化隐藏掉。

## 3. 任务说明

- W1：修复分页边界，公开测试不足以覆盖缺陷，隐藏测试覆盖非法输入、空集及边界。
- W2：在多文件任务板中实现原子批量状态变更，含验证、去重、状态转换与失败不写入。
- W3：对确定性生成的 CSV 进行清洗、去重与聚合，黄金结果完全可机读比对。
- W4：根据冻结资料生成报告，含过期公告与仅限测试环境的结果，重点看事实与冲突处理。
- W5：跨端接续手动清单；确认是同一任务、正确参数和执行主机，不把转发消息视为接续。
- W6：60秒模拟长命令与阶段记录；分开关闭客户端、断网和执行主机离线，不把进程类任务直接外推到多轮 Agent。

这些是受控的小型基准，不代表真实业务的全部难度；需要在正式批次补充用户真实但脱敏的代表任务。
如果试跑显示任务全部轻易完成、缺少区分度，应在正式评分前升级任务包和验收版本，并重跑相关对照；不能在正式结果出现后改题迎合某个赢家。

## 4. 专项试验

详见 `plan.json` 中 33 张测试卡以及 Excel。先完成试跑，再优先跑会改变判定的专项：R1/R3恢复副作用、S1/S3隔离、C1/C2停止撤权、X1增长、M1/M2改造、T1迁移、O1/O2证据链。

本地安全副作用服务：

```bash
python3 tools/effect_server.py --state-dir /绝对路径/新建测试状态目录 --port 0
```

它仅绑定127.0.0.1，输出实际端口。GET `/state` 查看计数；POST `/effect` 接收 `operation_id` 和 `drop_response`。
服务故意不去重；请求生效后可以关闭连接，便于检验框架是否核对未知结果。不得把它接到真实业务。
云/隔离容器若无法访问回环端点，需要单独部署受控等价工具；不要擅自暴露公网或在测试器中补上框架缺少的幂等机制。

## 5. 正式批次

试跑后冻结任务版本、客户端版本、有效配置、价格/credits时段和预算。
候选规模：6任务×3变体×3重复×4家=216次。按任务与变体分层；每次新工作区、新会话，缓存冷热和模型实际命中另记。
不能把新客户端会话等同供应商缓存全冷；依据usage中的缓存用量和试验条件报告。
此前计划的P2固定模型响应桩微基准本轮暂不启用，不计入四家固定模型结果。实际模型端到端时延与独立工具延时可以分别记录。
本轮不增加 Codex Flash、Luna、Astra、模型切换或自动升级实验。

## 6. 结果与停止条件

遇到模型不符、未授权数据/网络动作、预算不足、无法确认任务是否仍在执行、日志/产物丢失或试验环境被污染：停止该运行并保留原因，不静默重试。
失败的原始运行保留；配置修复后的重跑使用新ID，不能覆盖旧失败。
先按 `SCORING.md` 完成 66 组对照，再填 44 格等级；证据不足留空，不填“中”占位。
交付：四家结果表、44条一句话、原始运行索引、测试覆盖和限制；分别说明编码、文件/数据、跨端后台场景，不直接数“强”选冠军。
