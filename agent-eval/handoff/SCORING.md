# 评分与证据约定

## 评分对象

四套冻结配置：OpenClaw/Hermes/DSH + DeepSeek Flash；Codex家族 + GPT-6.1 Sol。
不同模型的产品结果不能直接解释成框架本身更聪明、更快或更省。三家同Flash也仍需记录系统提示、接口映射、工具和推理参数差异。

## 每次运行先判验收

- W1/W2：必选隐藏测试通过、无禁改内容；不以被测Agent自述“测试通过”为证据。
- W3：有效行、错误行、重复行与统计值符合黄金结果；空输出或少处理数据不算节省。
- W4：无关键事实错误；结论、来源和“未确认”区分正确；自动结构检查不是语义通过。
- W5：同一任务身份、原有要求、审批参数和输出一致；需要手动记录。
- W6：外部执行记录与声明的客户端/主机生命周期相符；程序结束不自动代表多轮Agent任务恢复。

失败、部分完成、取消及人工补救独立记录。计算单位成功任务成本时纳入失败尝试与补救；不能只挑成功样本。

## 三档归一化

每个维度对四家做6组成对比较。仅允许：A优、相当、B优、证据不足。
以 `plan.json` 的该维主判指标和护栏为准；相同质量门槛后再比较时间、成本、人工步骤或关键边界覆盖。
时间/费用差异15%是待审核的项目阈值，试跑后、正式比较前冻结；不是行业标准。跨变体方向不一致时需报告取舍，不能只选有利任务。

一家的3组有效对照：胜1、平0.5、负0，总胜分P：
- 强：P≥2.5。
- 中：0.5<P<2.5。
- 弱：P≤0.5。

任一影响分档的对照缺证据，该格暂不定档，证据状态填写待核/待测。
实际相当允许全部为中；不得强制配额或将默认设置、市场采用率、代码语言直接兑换成等级。
越权、密钥泄露、数据损坏等在对应场景另标不合格；不能被其他维度得分掩盖。

## 证据层次

官方声明、固定源码/配置确认、现场观察、重复对照验证分别记录。
架构合同可以证明能力范围；性能、成本、成功率和增长曲线必须有同口径运行数据才出效果等级。
公开数据不足不等于不支持。源码可见性优势与产品行为结果分开，托管不可见资源不记零。

## 审核顺序

先审范围、任务和判据；再审实际机制与原始结果；最后审等级和一句话。
旧V1评级已撤回。原weidu.xls保留为资料线索，其中CLI范围及旧能力判断不能直接复用。
同一能力只有一个主评分维度，其他维度可以引用影响，不重复加分。
